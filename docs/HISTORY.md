# 개발 경과와 결정 사항

Claude 와의 대화로 만든 프로토타입의 흐름을 정리한 문서. **왜 지금 모양이 되었는지**를 알아야 같은 실수를 반복하지 않는다.

## 1. 기획 단계
- 목표: 액션 게임을 주로 하는 디자이너도 만족할 "도파민" 코어. 기존 게임 복제, 체인 액션, 잔상·분신 류 아이디어는 모두 기각.
- 채택: **크기·질량 조작** — 한 손으로 이동, 다른 손으로 크기. 질량이 커지면 가속만 줄고, 충돌 피해는 순수 충격량.

## 2. 2D → 3D → 2D
- 3D 우주 버전(쿼터니언 시점, 1·3인칭, 지평선 중력 등)을 만들었으나 조작감이 2D 만 못해서 폐기 → `archive/prototype-3d/`.
- 3D 에서 가져온 것: **사방에서 몰려오는 무리 + 경험치 구슬** (뱀서류 구조).

## 3. 코어 다듬기
- 크기를 바꿔 무한 가속되는 버그 → 크기를 바꿔도 **속도 유지**, 크기 에너지 도입.
- 운동량 피해, 지속 회복, 넓은 맵·시야, 다양한 적, 적이 날아가 다른 적에게 피해(당구).
- 한 방에 너무 죽음 → 피해 곡선 완화 + 한 번에 최대 체력 60% 상한.

## 4. 소닉붐 → 체렌코프
- 처음엔 원형 링, 다음엔 그려 넣은 원뿔 → **디자이너가 강하게 거부**: "소리 속도를 정해두고 그걸로 계산하라는 것".
- 최종: 파면을 실제로 내보내고 교차선만 그림, 판정도 그 선. 범위·속도·피해를 여러 번 조정.
- 성운 테마 전환 때 이름·연출만 체렌코프 빛으로 바꿈 (메커니즘 동일, 매질 굴절률 2 → 진공 광속을 넘지 않음).

## 5. 무기·진화
- 무기 8종, 슬롯 4칸 → 3칸 → 다시 4칸.
- 진화 1차: "A 발동 시 B의 작은 효과" 방식 → **"두 메커니즘이 합쳐진 느낌이 안 든다"** 피드백.
- 진화 2차: 무기의 작동 방식 자체를 섞는 28종으로 전면 재작성. 디자이너가 대부분의 사양을 직접 지정 (CONTENT.md 의 효과 설명이 최종본).
- 진화는 두 무기를 **슬롯 1칸으로 합침**, 진화 재료는 다른 진화에 재사용 불가.
- 실수 기록: "추가 탄환+특이점 = 블랙홀이 탄환처럼" 을 탄환 옆에 블랙홀을 추가로 쏘는 걸로 잘못 만들었다 → **사양은 문자 그대로**.

## 6. 밸런스
- 봇 시뮬레이션으로 검증하는 방식 정착 (`tools/sim`). 초기 측정은 강한 조합이 적을 다 잡아 수치가 천장에 막히는 문제가 있었음 → 적 체력 30배 + 무적 봇의 "후반 모의"로 해결.
- 추가 탄환이 압도적 → 여러 차례 너프 + 탄환 속도를 **충돌 세기에 비례**하게.
- 연쇄 번개가 고정 피해라 Lv1 에도 충돌보다 몇 배 셌음 → **충돌 충격량 × (1 + 0.5(Lv−1))**.
- 저절로 발동하는 무기(미사일·지뢰·자기장·위성) 화력 0.6배 — 균형이 깨지더라도 "박는 재미"가 우선.
- 시간에 따라 적 체력·단단한 적 비중 증가 (긴장감), 튜토리얼에는 미적용.

## 7. 연출·UI
- 화면 글자 제거: 싹쓸이, WAVE, 음속 돌파, 초신성 준비됨, 운동량 게이지, 슬로모션.
- 빛나는 VFX, 경험치/적 구분, 불 밝기 누적 방지(lighten 합성), 불 전용 저해상도 레이어(최적화).
- Esc 설정 메뉴(볼륨·흔들림·번쩍임·키 재지정), 효과음 동시 재생 상한, 흔들림 상한.
- 사망: 별이 터지며 흩어짐 → "파괴되었습니다" + 기록 + 딜 기여도(블루 아카이브 결과 화면 참고).
- 모든 카드·무기 칸에 코드로 그린 아이콘.
- 개발자 모드 `hichanplay`.

## 디자이너 성향 (다음 작업자를 위해)
- 피드백이 빠르고 직설적이다. 같은 지적을 두 번 받으면 크게 불만스러워한다 → 지시를 정확히 반영하고, 반영했는지 실제로 확인할 것.
- 물리적으로 말이 되는 것, 창발적인 것을 좋아한다. 연출용 가짜를 싫어한다.
- "강한 건 강해도 되지만 약한 건 너무 약하면 안 된다."
- 숫자 결과는 표·그래프로 보길 원한다 (예: 8×8 밸런스 표, 딜 기여도 그래프).
- 실험 결과가 이상하면 측정 방식부터 의심한다 — 측정의 한계를 숨기지 말 것.
